# 符文骰子工程交接包：M1.1

## 用途

本目录是从 `D:\NewOne\Client-Dice` 制作的可迁移交接包，目标是在另一台机器或另一开发环境中继续开发，不改变原项目的相对资源结构。

## 当前成果

- 阶段甲：原作森林牌桌基线。
- 阶段乙：原作九级三维骰子本体。
- 阶段丙：多骰投掷、真实三维碰撞、停稳占位、同级合并、数字深度遮挡。
- M1.1：三维战斗垂直切片，包含攻击、治疗、护盾、敌方意图、回合状态机、验收模式和三维物理骰子。
- 游戏内界面和操作提示保持中文。

## 已验证证据

- M1.1 自动测试：32/32 通过。
- 三维战斗场景生成：通过。
- Windows x64 构建：通过。
- 实际工程目录下的三维战斗包冒烟：通过，进入第二回合。
- 详细报告：`Docs/Delivery/M1.1/TEST-REPORT.md`。
- 阶段丙报告：`Docs/Demo-C-多骰碰撞合并-交付说明.md`。

## 新环境接续步骤

1. 将本目录作为工程根目录打开。
2. 使用团结引擎 1.10.2；当前验证编辑器显示为 `2022.3.62t14`。
3. 让团结引擎重新生成 `Library`，不要复制旧机器的 `Library`。
4. 等待脚本编译完成后，检查 `Assets/Scenes/BattleM1.unity`。
5. 运行 `Builds/M1/Windows/RuneDiceM1.exe`，或在编辑器内打开 `BattleM1` 场景。
6. 用 `F10` 打开验收模式，优先测试 M1-A 到 M1-G。
7. 新环境首次构建时，使用 `Assets/Editor/M1Build.cs` 中的构建菜单重新生成 Windows 包。

## 重要接续约束

- `Assets/DemoA/OriginalAssets/GameObject/Desk Base - Forest.prefab` 是原作牌桌视觉资源。
- `Assets/DemoB/OriginalAssets/GameObject/Regular Dice View.prefab` 是原作九级三维骰子视觉资源。
- `Assets/DemoB/OriginalAssets/PhysicsMaterial/Rubber.physicMaterial` 是原作物理材质基线。
- `Assets/DemoC/Generated/骰子数字深度遮挡.mat` 和对应着色器用于遮挡背面数字。
- M1 战斗骰子必须继续使用三维 `Rigidbody`、`BoxCollider` 和原作九级视觉；不要回退到二维刚体或固定图片旋转。
- 交付包未包含本机 `.com-unity-codely.json`，新环境应重新建立自己的编辑器桥接配置，避免复用旧机器端口和绝对路径。
- `Docs/Delivery/M1.1/KnownIssues.md` 记录了当前尚未签收的风险。
