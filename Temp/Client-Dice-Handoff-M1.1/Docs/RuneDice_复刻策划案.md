# Rune Dice 核心玩法复刻策划案

> 文档状态：提案 v0.1
>
> 目标工程：`D:\NewOne\Client-Dice`
>
> 引擎：团结引擎 1.10.2（Unity 2022.3.62t14）
>
> 核心原则：先复刻“投掷、碰撞、合并、结算、选路”的体验闭环，再扩充职业、敌人、遗物和长期成长。

## 1. 项目目标

将当前的物理骰子合并 Demo 发展为一款可独立游玩的“物理合并 + 回合战斗 + Roguelike 路线选择”游戏。

玩家在每回合投掷一枚骰子，使场上相同类型、相同等级的骰子碰撞并升级。一次投掷可以引发连续合并；合并后的骰子进入效果队列，依次造成攻击、治疗、护盾或其他职业效果。随后敌人按预告行动。玩家通过地图节点选择战斗、奖励和风险，最终击败 Boss 完成一局。

复刻目标分为三层：

1. **体验复刻**：还原原作最有辨识度的战斗节奏和策略选择。
2. **系统复刻**：逐步补齐地图、奖励、商店、遗物、符文、存档和图鉴。
3. **内容复刻**：在基础系统稳定后，按职业和生物群系批量迁移已有资源与配置。

首要成功标准不是“类名和原工程完全一致”，而是玩家能够感受到以下循环：

> 看敌方意图 → 判断合并路线 → 瞄准并投掷 → 观察连锁碰撞 → 按队列触发骰子效果 → 承受敌方行动 → 调整构筑 → 继续选路

## 2. 设计支柱

### 2.1 物理带来计划外收益

投掷前可以瞄准和预判，但碰撞结果不能被完全控制。优秀操作提高合并概率，连续碰撞则制造惊喜。随机性应来自物理和构筑组合，而不是单纯的数值摇点。

### 2.2 合并本身就是出牌

骰子不是只提供分数。每次有效合并都会排入战斗效果，骰子类型、等级和连锁顺序共同决定回合收益。

### 2.3 敌方意图驱动决策

敌人在玩家行动前展示下一步动作。玩家需要在输出、治疗、护盾、控制和经济收益之间选择本回合的合并目标。

### 2.4 一局形成独特构筑

骰子库、遗物和符文共同改变规则。构筑应改变玩家“想让哪些骰子相撞、在什么时机相撞”，而不仅是增加百分比。

### 2.5 每个里程碑都可玩

所有系统按垂直切片扩张。没有完成战斗闭环前，不投入大量精力制作完整地图、图鉴、成就或平台功能。

## 3. 已确认机制与待确认规则

### 3.1 从导出工程可以确认

- 正式流程包含 Boot、主菜单、角色选择、地图、战斗、统计六类场景。
- 战斗包含初始化、回合准备、玩家行动、物理收尾、战斗结算、充能/刷新六个主要阶段。
- 同类骰子存在碰撞合并、合并队列和连锁合并机制。
- 骰子效果至少覆盖攻击、治疗、护盾、金币、炸弹、毒、冰冻、眩晕等类型。
- 敌人有行动预告和动作序列，动作包含等待、移动、近战、远程、施加效果、召唤、治疗等。
- 地图节点包含普通战斗、精英、MiniBoss、Boss、事件、商店、升级、宝箱和祭坛。
- 局内数据包含生命、金币、骰子库、遗物、符文/待使用物品、地图进度和统计。
- 局外数据包含图鉴、解锁条件、累计统计、教程与角色偏好。

### 3.2 第一版采用的产品决策

以下规则是为了尽快形成可玩的复刻版本而提出，后续可以根据原版实机验证调整：

- 每回合只允许一次主动投掷。
- 待投掷骰子从玩家骰子袋中随机抽取，并提前显示下一枚。
- 只有“类型相同且等级相同”的玩家骰子可以合并。
- 合并结果等级加一，继承该类型的效果定义。
- 每个合并结果进入本回合结算队列；连锁合并按实际发生顺序进入队列。
- 骰子全部静止或超过最大等待时间后，进入效果结算。
- 玩家效果结算完毕后，存活敌人依次执行已预告动作。
- 首版等级上限为 6，达到上限后不再继续合并。
- 首版战斗场地无格子，使用当前 Demo 的自由 2D 物理。

### 3.3 需要原版实机或逆向继续确认

- Master Dice 与玩家骰子库的准确关系：直接抽取、复制场上骰子还是独立触发器。
- 合并后原骰是否留场、消耗、重生，以及战斗结束后的骰子持久规则。
- 多次合并的效果结算顺序、目标选择方式和连锁加成公式。
- 骰子睡眠判定、磁吸辅助、碰撞优先级与防止重复合并的精确规则。
- 敌人站位、玩家角色站位以及近战/远程目标规则。
- 战斗刷新阶段具体补充多少骰子，是否有场上数量下限。
- 原作各职业初始骰子库、基础生命和升级曲线。
- 商店、升级、祭坛、宝箱的原始价格和概率。

这些未确认项不阻塞首个垂直切片，但必须集中记录，不能分散成代码里的隐含假设。

## 4. 完整游戏循环

```text
主菜单
  ├─ 新游戏 → 选择角色/职业 → 选择难度 → 生成地图
  └─ 继续游戏 → 读取局内存档

地图节点
  ├─ 战斗：普通 / 精英 / MiniBoss / Boss
  ├─ 成长：升级 / 宝箱 / 商店
  └─ 风险：事件 / 祭坛

节点结算
  ├─ 获得金币、骰子、遗物或符文
  ├─ 调整构筑与生命
  └─ 保存进度 → 返回地图继续选路

Boss 胜利或玩家死亡
  └─ 局内统计 → 更新局外解锁/图鉴 → 返回主菜单
```

单局首版目标时长为 20～35 分钟；完整内容版可以扩展到 45～60 分钟。

## 5. 战斗系统

### 5.1 战斗阶段

每个回合严格按以下阶段运行：

1. **回合准备**
   - 清理上回合临时状态。
   - 敌人选取并展示下一行动。
   - 显示本回合待投掷骰子。
2. **玩家瞄准**
   - 玩家拖拽确定方向和力度。
   - 显示预测线，但不提供完全精确的多次反弹轨迹。
3. **玩家投掷**
   - 生成或激活 Master Dice。
   - 在物理结算期间禁止第二次投掷。
4. **物理收尾**
   - 处理碰撞、合并、爆炸和连锁反应。
   - 等待全部刚体进入睡眠，设置 4 秒兜底超时。
5. **玩家效果结算**
   - 锁定输入。
   - 按合并队列逐个播放效果和数值变化。
   - 每个效果结束后检查敌人死亡。
6. **敌方行动**
   - 存活敌人按站位顺序执行预告动作。
   - 每个动作后检查玩家死亡。
7. **回合刷新**
   - 补足必要的场上骰子。
   - 抽取下一枚骰子。
   - 进入下一回合，或进入胜负结算。

### 5.2 骰子模型

每枚骰子至少包含以下数据：

| 字段 | 说明 |
|---|---|
| ID | 稳定配置 ID |
| 类型 | Attack、Heal、Shield 等玩法类型 |
| 等级 | 首版 1～6 |
| 阵营 | Player / Enemy / Neutral |
| 基础数值 | 对应等级的效果值 |
| 合并规则 | 是否允许连锁、是否阻断其他合并 |
| 物理参数 | 质量、弹性、阻力、碰撞半径 |
| 效果列表 | 一个骰子可以组合多个效果 |
| 表现资源 | Sprite、命中特效、音效、说明文本 |

首版支持六种核心骰子：

| 骰子 | 合并效果 | 战术价值 |
|---|---|---|
| 攻击 | 对目标造成等级成长伤害 | 基础输出 |
| 治疗 | 恢复角色生命 | 生存 |
| 护盾 | 获得本回合/下回合护盾 | 预判防御 |
| 毒 | 施加持续伤害层数 | 长线输出 |
| 炸弹 | 对全部敌人或范围目标造成伤害 | 清杂与连锁 |
| 金币 | 战斗内获取少量金币 | 牺牲即时战力换成长 |

第一里程碑只实现攻击、治疗、护盾；毒、炸弹、金币放入第二批内容。

### 5.3 合并规则

- 碰撞开始时读取双方状态，只有双方均未被锁定才能尝试合并。
- 骰子类型和等级都相同才满足默认合并条件。
- 使用稳定的合并事务：先锁定两枚骰子，再创建结果，最后销毁原对象。
- 同一物理帧中的重复碰撞不能让一枚骰子参与两次合并。
- 新骰子保留双方平均速度，并获得轻微向上冲量，以形成可观察的连锁机会。
- 新骰子应有短暂的合并保护时间，防止生成瞬间重复触发异常。
- 合并记录包含类型、原等级、新等级、发生位置、时间戳和连锁深度。
- 达到最高等级时，碰撞只产生强化反馈，不再升级。

### 5.4 连锁与计分

连锁的核心价值应落在战斗效果，而不只是 UI 分数。建议规则：

- 1.25 秒内由同一次投掷持续触发的合并属于同一 Chain。
- Chain 深度从 1 开始。
- 首版效果倍率为 `1 + 0.25 × (ChainDepth - 1)`，最高 2 倍。
- UI 分数用于即时反馈和局内统计，不作为通关硬门槛。
- 结算队列显示即将触发的骰子、等级、目标和倍率。

倍率需要通过试玩验证。如果连锁已经因高等级骰产生指数成长，则应降低或移除额外倍率。

### 5.5 单位、生命与伤害

- 玩家首版只有一个角色单位。
- 敌方支持 1～3 个单位。
- 伤害先扣护盾，再扣生命。
- 护盾默认在敌方行动结束后清空；具体保留规则可由骰子配置覆盖。
- 中毒在敌方行动开始前触发，触发后层数衰减 1。
- 死亡单位立即退出后续行动队列。
- 敌人全灭时取消尚未执行的敌方动作，进入胜利结算。

### 5.6 敌方意图与 AI

首版使用可预测的动作序列，而不是复杂行为树：

```text
EnemyConfig
  └─ ActionSequence: Attack(5) → Wait → Defend(4) → Attack(8) → loop
```

敌人需要显示：

- 下一行动图标。
- 目标。
- 预计伤害、护盾、治疗或状态层数。
- 特殊规则说明。

首批敌人：

1. **近战哥布林**：交替等待和单体攻击，用于教学。
2. **弓手**：稳定远程攻击，迫使玩家关注防御。
3. **萨满**：攻击与自我强化循环。
4. **精英守卫**：护盾和重击交替。
5. **首个 Boss**：两阶段行动序列，生命低于 50% 后提高压力。

## 6. 构筑与成长

### 6.1 骰子库

骰子库是本局可以抽到的骰子集合，每项记录类型、等级和数量。

- 新游戏按职业获得固定初始牌组。
- 战斗奖励可以三选一加入骰子。
- 升级节点提升一枚骰子的初始等级。
- 商店可以买入或移除骰子。
- 骰子库过大将降低关键骰子出现概率，形成构筑取舍。

首版使用 8 枚初始骰：4 攻击、2 护盾、2 治疗。

### 6.2 遗物

遗物是整局持续生效的规则修改器。首版优先设计能改变投掷和合并决策的遗物：

| 遗物 | 建议效果 |
|---|---|
| 幸运马蹄 | 每场第一次未形成合并的投掷，返还一次投掷机会 |
| 磁力核心 | 同类型骰子在近距离时产生轻微吸引 |
| 爆裂骰杯 | 每次三连合并对所有敌人造成少量伤害 |
| 急救手册 | 每场第一次低于 30% 生命时生成一枚治疗骰 |
| 锻造锤 | 获得骰子时有概率直接提升一级 |

### 6.3 符文/消耗品

符文是有限次数的主动能力，首版保留两个槽位：

- 重掷：更换下一枚待投掷骰子。
- 推力：对场上指定骰子施加一次冲量。
- 冻结时间：短暂减慢物理模拟，辅助瞄准。
- 修复：恢复固定生命。

符文不应取代核心投掷，而是用于修正坏局面。

## 7. 地图与节点

### 7.1 首版地图结构

首个可玩版本使用固定模板加随机节点内容：

- 共 8 行。
- 每行 2～3 个节点。
- 相邻行之间形成分叉与汇合。
- 第 1 行固定普通战斗。
- 第 4 行固定精英或休整选择。
- 第 8 行固定 Boss。
- 同一路径不能连续出现两个商店。

程序化生成应在玩法稳定后再扩展，第一版先确保每局节奏可控。

### 7.2 节点定义

| 节点 | 首版功能 | 优先级 |
|---|---|---|
| 普通战斗 | 基础敌人组合，掉落金币和骰子选择 | P0 |
| Boss | 单局终点 | P0 |
| 宝箱 | 三选一遗物 | P1 |
| 升级 | 免费提升一枚骰子 | P1 |
| 商店 | 买骰子、买遗物、移除骰子 | P1 |
| 精英 | 高难战斗，稳定掉遗物 | P1 |
| 事件 | 文本选择与风险收益 | P2 |
| 祭坛 | 付出生命/金币换特殊改造 | P2 |
| MiniBoss | 阶段性强敌 | P2 |

## 8. 奖励与经济

首版只使用一种货币：金币。

- 普通战斗：基础金币 + 骰子三选一。
- 精英战斗：更多金币 + 遗物。
- Boss：完成本局。
- 商店：出售 3 枚骰子、2 件遗物，提供 1 次移除服务。
- 奖励界面允许跳过，跳过可以获得少量金币，避免被迫污染构筑。

建议初始占位值：

| 项目 | 数值 |
|---|---:|
| 初始金币 | 50 |
| 普通战斗金币 | 15～25 |
| 骰子售价 | 40～70 |
| 遗物售价 | 100～160 |
| 移除骰子 | 75，之后每次 +25 |
| 跳过骰子奖励 | 15 |

这些数值只用于首轮可玩性测试，不视为最终还原值。

## 9. 角色与职业

不要在底层战斗没有稳定前同时开发多个职业。首版仅实现一个“均衡冒险者”：

- 生命：60。
- 初始骰子：攻击 ×4、护盾 ×2、治疗 ×2。
- 被动：每场战斗第一次形成三连合并时，获得 3 点护盾。

后续职业按照“核心骰子 + 独有机制”扩展：

- 战士：护盾、眩晕、压制。
- 游侠：穿透、击退、狙击。
- 法师：火焰、冰冻、闪电、奥术。
- 德鲁伊：成长、荆棘、再生、缠绕。
- 盗贼：毒、闪避、背刺、致盲。
- 圣骑士：治疗、神圣、牺牲、怒气。
- 死灵法师：灵魂、诅咒、吸取、死亡标记。
- 吟游诗人：激励、力量、弱化、返场。

每个职业在加入前必须满足：至少 4 个独特骰子、1 个明确核心循环、1 套初始构筑和 3 个专属遗物。

## 10. UI 与反馈

### 10.1 战斗 HUD

必须显示：

- 玩家生命和护盾。
- 敌人生命、状态和下一行动。
- 当前回合。
- 下一枚待投掷骰子。
- 当前骰子库入口。
- 遗物和符文栏。
- 合并结算队列。
- 暂停、倍速和设置。

### 10.2 关键反馈

- 可以合并的同类骰子在靠近时有轻微高亮。
- 合并需要缩放、闪光、数字跳变和音效四层反馈。
- 连锁层数越高，音高、震屏和粒子强度逐级增加。
- 敌方伤害在动作开始前再次强调目标和数值。
- 玩家效果和敌方效果不能同时结算，避免读不清。
- 提供 1×、2×、3×表现倍速，但物理瞄准阶段保持 1×。

### 10.3 新手引导

教程只教四步：

1. 拖拽并投掷。
2. 相同骰子可以合并。
3. 合并会触发战斗效果。
4. 观察敌人下一行动。

构筑、地图和遗物通过首次出现时的短提示说明，不制作长篇强制教程。

## 11. 数据配置方案

建议把玩法数值全部放在 ScriptableObject，运行时逻辑只消费配置。

### 11.1 核心配置

- `GameBalanceConfig`：全局物理、回合和经济参数。
- `DiceDefinition`：骰子类型、各级数值、效果与表现。
- `CharacterDefinition`：生命、初始骰子库、被动。
- `EnemyDefinition`：生命、动作序列、奖励权重、表现。
- `EncounterDefinition`：敌人组合和战斗场地。
- `RelicDefinition`：触发时机、参数和稀有度。
- `ConsumableDefinition`：主动效果和使用目标。
- `MapDefinition`：行数、节点权重和生成约束。
- `RewardTable`：按节点和进度定义奖励池。

### 11.2 稳定 ID

所有会进入存档的数据必须使用手工维护的字符串 ID 或 GUID，禁止用资源名、数组下标或枚举序号直接作为永久存档标识。

### 11.3 运行时数据与配置分离

- 配置描述“它是什么”。
- Runtime Model 描述“本局现在是什么状态”。
- View 只负责显示和动画。
- 战斗结算通过命令/事件传递结果，不允许 UI 直接改生命或金币。

## 12. 存档与统计

### 12.1 最小存档

首版需要自动保存：

- 随机种子和当前地图节点。

## 15. 平衡与测试指标

每个可玩版本至少记录以下数据：

- 每场战斗平均回合数：目标 4～8。
- 单次投掷形成至少一次合并的比例：目标 55%～75%。
- 形成二连及以上 Chain 的比例：目标 15%～30%。
- 普通战生命损失：目标为最大生命的 8%～18%。
- 首个 Boss 到达率和击败率。
- 骰子选择率、遗物选择率和跳过率。
- 玩家因“不理解规则”造成的失败次数。

出现以下情况时优先修规则而不是堆数值：

- 玩家等待物理停止的时间比决策时间更长。
- 高等级骰子占满场地，导致无可操作空间。
- 某类骰子只在数值上更强，没有改变投掷目标。
- 敌方意图虽然显示，但玩家无法通过本回合决策响应。

## 16. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 原版方法体丢失 | 无法机械复制精确规则 | 以实机录像、配置资产和可观察结果建立行为规格 |
| 物理结果不稳定 | 难以调试和复现 | 固定时间步、确定随机种子、记录每次投掷输入 |
| 连锁合并产生竞态 | 重复销毁或重复结算 | 合并事务锁、唯一事件 ID、自动化压力测试 |
| 内容量过早膨胀 | 系统未稳时返工巨大 | 每个里程碑限制骰子、敌人和遗物数量 |
| 旧资源导入关系复杂 | 材质、动画或字体失效 | 只迁移实际使用资源，建立新工程内干净 Prefab |
| 复刻内容对外发布 | 可能涉及素材与品牌权利 | 对外发布前确认授权；必要时替换名称、美术和音频 |

## 17. 下一步建议

立即进入 M1，不先做地图。具体开发顺序：

1. 将当前单文件 Demo 拆成正式的战斗数据、物理骰子、合并服务和表现层。
2. 完成可复现的瞄准投掷与物理结束判定。
3. 建立战斗状态机和合并结算队列。
4. 加入玩家、敌人、生命、护盾和敌方意图。
5. 实现攻击、治疗、护盾三种骰子。
6. 做一场完整战斗的 UI、胜负和调试工具。
7. 连续试玩并冻结基础规则后，再进入地图与奖励。
