## 追加：字体链问题**定论**（B1 前提推翻，Build B/C 取消）

### 结论（双证据，已闭合）
**5 套 NotoSans CJK 字体与全部 `.ttf` 都没有进包。进包的字体载荷只有 Jersey10 拉丁字体的 Material + Atlas，约 1MB 量级。**

**证据一 · 包内字符串检索**（工程负责人提供的证伪路径，很好用）——资产名以 ASCII 存于序列化文件：
- `NotoSans` / `NotoSansSC` / `NotoSansJP` / `NotoSansKR` / `NotoSansTC` / `.ttf` → **全部 0 命中**
- `Jersey10` → 1 文件 2 处，且只是 `Jersey10-Regular SDF Material`、`Jersey10-Regular SDF Atlas`（仅材质与图集，图集约 0.99MB = `sharedassets0.assets.resS` 991,680 字节）
- 对照组：`Desktop_Wooden` 1、`BattleFlow` 3、`符文` 2 —— 均命中，证明检索方法有效

**证据二 · 字节账目完全闭合**：
`TuanjiePlayer.dll` 47,477,592 ＋ `_Data` 35,070,525（含 `Managed` 24,454,352、`Resources` 4,821,808）＋ `MonoBleedingEdge` 9,333,942 ＋ `exe` 464,384 ＋ 崩溃处理器 ~1,170,776 ＝ **93,517,219**，与构建日志 `93514659` **仅差 2,560 字节**；且 `find _Data -size +5M` **为空**（`_Data` 内无任何 >5MB 文件）。

### 关键更正（工程负责人对，我错了一半）
- 我原先的机制解释「TMP missing script → 组件数据无法被依赖收集遍历 → 引用不入包」**是错的**。
- 实测反证：`Jersey10-Regular SDF Material` / `SDF Atlas` **确实进了包**，说明**构建期依赖收集走序列化数据层的 PPtr，不要求 `m_Script` 可解析**。missing script（F16）**不会**自动把引用挡在包外。
- 正确成因：这 5 套 NotoSans CJK 字体**在依赖链上根本未被引用到**（TMP fallback 表 / `TMP_Settings` 未参与收集），而非"被缺脚本挡住"。
- 工程负责人提出的「≈11.7MB 缺口恰似 NotoSansSC」经实测被否——那是我把 `Managed` 粗估为 ≈15MB 造成的误差，实测 `Managed` = 24.45MB，账目随即闭合。
- **方法论沉淀**：包体归属问题**用包内字符串检索 + 字节账目定论，不要用机制推理替代实测**。

来源：`https://developers.weixin.qq.com/minigame/dev/guide/base-ability/code-package.html`
> 「代码包总大小不能超过 **30M**，单个分包不限制大小，主包不超过 **4M**。」
- **主包 ≤ 4MB** ✓；**总包 ≤ 30MB**（**原记 20MB 作废**）；**单个分包大小不限**（团队调研里"单个独立分包 ≤4MB"一句是错的）。
- ⇒ B3 的腾挪空间比原设想大。
- 上传白名单含 `wasm` / `ttf` / `astc` / `bin` / `json` / `scene` / `prefab` / `gz` / `br` 等。

### 已核实的官方 FAQ 风险
README 明示：若游戏代码**从未使用 WXSDK 任何 Runtime 能力**，团结导出时会**把微信 Runtime 裁剪掉**，微信开发者工具运行报错 → 解法是在合理位置引用一次 WXSDK。这条是真风险，须在 A1 后验证。
