# 符文之骰微信小游戏开发方案

## 1. 项目目标

使用团结引擎 1.10.2 制作一款竖屏微信小游戏。借鉴物理投骰、同类融合、连锁反应和肉鸽构筑等通用机制，使用原创名称、数值、美术、音频和关卡内容。

核心体验：

```text
瞄准投骰 → 物理碰撞与反弹 → 同类骰子融合 → 攻击与连锁反馈 → 局内构筑
```

## 2. 技术基线

- 引擎：团结引擎 1.10.2（2022.3.62t14）
- 目标平台：微信小游戏
- 屏幕：竖屏，720 × 1280 设计基准，适配安全区
- 表现：2.5D 视觉，正交相机
- 物理：Physics2D
- 渲染：Built-in Render Pipeline
- UI：UGUI + TextMeshPro
- 配置：ScriptableObject；后期视规模评估外部表格生成
- 测试：EditMode 规则测试 + PlayMode 核心闭环测试 + 微信真机验证

## 3. 角色分工

| 角色 | 职责 | 禁止事项 |
|---|---|---|
| producer | 拆解任务、确认范围、管理风险与交付 | 不越过确认点扩大功能 |
| planner | 玩法流程、数据需求、验收标准 | 不修改代码或资源 |
| programmer | 工程设置、业务代码、测试、构建验证 | 不修改美术方向或增加未批准玩法 |
| artist | 场景占位视觉、模型、材质、特效和资源整理 | 不修改业务代码 |
| reviewer | 只读审查、测试缺口、性能与范围检查 | 不修改工程文件 |

阶段 0 的场景结构由 programmer 搭建；占位视觉与模型由 artist 设计并整理。正式资源从阶段 2 起单独审批。

## 4. 系统边界

- `Core`：游戏状态、流程和服务注册
- `Input`：鼠标/触摸输入、瞄准手势
- `Dice`：骰子实体、类型、等级和生命周期
- `Fusion`：融合资格、冲突消解和连锁队列
- `Combat`：伤害、生命、死亡和胜负
- `UI`：HUD、安全区和交互反馈
- `Platform`：微信生命周期、存储、音频和分享接口
- `Configs`：骰子、敌人、符文和圣物配置

物理碰撞只产生事实事件；融合和伤害由独立规则层结算，避免业务规则散落在 `OnCollisionEnter2D` 中。

## 5. 分阶段路线

### 阶段 0：工程基线

目标：建立可持续开发的竖屏 Physics2D 工程。

- 设置产品信息、竖屏方向和 720 × 1280 基准
- 建立 `Assets/Game` 目录和程序集边界
- 创建 `RuneDiceDemo` 场景
- 建立正交相机、战斗区域、发射区、融合系统占位对象和 UI 根节点
- 配置物理层和固定时间步长
- 使用简单几何体作为占位视觉
- 完成编译、Console 和场景结构检查

验收：工程可由团结引擎 1.10.2 打开；无持续编译错误；场景结构完整；Game 视图符合竖屏构图。

### 阶段 1：最小可玩 Demo

目标：验证投掷、碰撞、融合、伤害和重置的完整闭环。

- 单指/鼠标拖拽瞄准，松手发射
- 骰子与边界、骰子发生 Physics2D 碰撞
- 相同类型和等级的两个骰子融合为高一级骰子
- 一对碰撞对象只结算一次
- 融合产生范围伤害和占位反馈
- 一个静态敌人、胜利状态和重新开始按钮
- EditMode 测试覆盖融合资格与伤害计算

验收：连续重置 20 次无异常对象累积；不穿墙；融合结果稳定；编辑器目标 60 FPS。

### 阶段 2：战斗原型

- 回合制投掷与骰子队列
- 普通、火焰、闪电三种原创骰子
- 敌人行动、玩家生命和战斗结算
- 连锁融合、伤害数字、镜头与粒子反馈
- 战后奖励三选一

### 阶段 3：构筑原型

- 骰子池与局内升级
- 主动符文和被动圣物
- 商店与构筑修正
- 至少一套完整原创流派
- 配置驱动和平衡日志

### 阶段 4：肉鸽完整局

- 随机路线
- 普通、精英、事件、商店和 Boss 节点
- 一名原创英雄
- 局外解锁与本地存档
- 从开局到 Boss 的完整流程

### 阶段 5：微信小游戏发布基线

- 接入微信小游戏转换 SDK
- 处理安全区、触摸、前后台、音频恢复和本地缓存
- Wasm/资源分包与首屏加载优化
- 微信开发者工具、Android 和 iOS 真机验证
- 监控首屏时间、峰值内存、包体和帧率

## 7. 性能与微信验收门槛

- 中端真机目标 60 FPS；复杂场面最低可接受 30 FPS
- 避免运行时频繁实例化，骰子和反馈使用对象池
- 控制透明叠加、粒子数量、材质种类和 Shader 变体
- 不以编辑器表现代替微信开发者工具和真机结果
- 每个阶段结束记录 CPU、GC Alloc、内存和活跃物理对象数量

## 8. 风险

1. 物理结果过度随机会削弱操作感，需要限制速度、弹性和融合窗口。
2. 连锁融合可能重复结算，需要唯一事件和帧内冲突消解。
3. 微信小游戏转换 SDK 与团结引擎补丁版本需要持续验证。
4. 资源分包、音频恢复和不同微信版本只能通过真机回归确认。
5. 只复刻通用机制，不复制原作受保护的美术、音频、文本、角色和关卡。
