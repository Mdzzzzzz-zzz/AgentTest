## 第 1 步 · 装「微信小游戏转换 SDK」

手册 `WechatSDK.html` L125 原文：「团结小游戏平台**默认集成了微信小游戏转换 SDK 插件**…**若您的团结引擎未显示该插件，请按照以下步骤手动安装**」。

**⚠️ 本项目注意**：实测在 `Packages\`、`Library\PackageCache\`、`Assets\` 三处**都查无**该 SDK，引擎安装目录也无 `WX-WASM-SDK` ⇒ **大概率需要手动装**。

先看第 2 步的 **Sub Platforms** 是否显示 **Install Support**（那是缺 SDK 的信号，可直接点它试装）。若装失败，用手册给的两条路：

### 路 A · Git 添加（手册推荐）
> **Window → Package Manager** → 点左上角 **"+" → Add package from git URL…** → 填入：
```
https://github.com/wechat-miniprogram/minigame-tuanjie-transform-sdk.git
```
手册附注：**使用该方法需要确保本地已正确安装和配置 Git。**

### 路 B · 直接下载插件导入
> 下载「微信小游戏转换SDK插件」package，**导入工程**。
> 手册原文：此方式完成后可以看到在**游戏工程 assets 文件夹下有 `WebGLTemplates` 和 `WX-WASM-SDK` 这两个新增文件夹**。
> 下载地址（手册里的链接）：`https://game.weixin.qq.com/cgi-bin/gamewxagwasmsplitwap/getunityplugininfo?download=1`

### 装完的验收（硬判据）
**`Assets\` 下出现 `WebGLTemplates` 与 `WX-WASM-SDK` 两个文件夹** ⇒ 装好了。

### 两个已知坑（手册「相关问题」）
- **brotli 报错**：早期微信 SDK 调用了 WebGL 平台的 brotli 压缩工具 ⇒ **安装微信小游戏平台时请同时安装 WebGL 平台**。最新版已解决。
- **Tuanjie 1.1.0 专用坑**：1.1.0 的 WeixinMiniGame 平台自带的小游戏转换插件与项目不兼容，需**卸载并把 `Assets` 下的 `WebGLTemplates` 和 `WX-WASM-SDK-V2` 删掉**，再装旧版 SDK package。
  ⚠️ **本项目是 1.10.2，不是 1.1.0**，应不适用；但**若第 1 步装完报"不兼容"，就按这条回退**。

## 第 2 步 · 切到 MiniGame 平台并激活微信子平台

手册 `AutoStreamingDemo.html` §2「配置构建文件」原文步骤：

1. **File → Build Settings** → 点 **Switch Platform** 切换平台至 **MiniGame**。
   （手册注：引擎**默认将自动安装**各小游戏平台 SDK package。）
2. **Build Settings** 界面右侧 **"Sub Platforms"** 会出现 **Add Build Profile** 按钮。
   **若该处显示的是 "Install Support"，表示缺失该平台的 SDK package，可点击安装。**
3. **Inactive / Active** 按钮用于**激活小游戏子平台** —— **仅支持同时激活一个平台**。
   ⇒ 把**微信**那一个点成 **Active**。
4. 点 **Add Build Profile** 后，**Projects → Assets → Settings → Build Profiles** 资产界面会出现新增的 Build Profile 资产。

> ⚠️ **本项目注意**：上次构建把 `activeBuildTarget` 留在了 `WeixinMiniGame`。如果 Build Settings 打开时已经是 MiniGame 平台，**Switch Platform 可能已是灰的/已完成**，直接做第 2~4 步即可。
> ⚠️ 这一步是**这次失败的关键**：上次我们是绕开 Build Profile、直接用脚本 `BuildPipeline.BuildPlayer` 打 `WeixinMiniGame` 目标，结果引擎落了 WebGL 默认模板。**必须走 Build Profile + Active 激活。**

## 第 3 步 · 填 Build Profile 的导出参数

打开该 Build Profile 的 Inspector（手册给的两种方式，任选）：
- 单击 **Projects → Assets → Settings → Build Profiles** 里的文件图标；或
- 双击 **File → Build Settings** 里 Build Profiles 框内的文件。

**Build Path 必填**（手册原文：「建议您先在 **Build Path** 处填写有效路径，**若未填写并在 Build Settings 中选中，引擎将报错提示**」）。

手册要求填写的字段：
| 字段 | 说明 | 本项目建议值 |
|---|---|---|
| **游戏Appid** | 可从小游戏开发工具点 register 申请正式 AppID；**测试 AppID 部分功能受限** | 有正式 AppID 就填；没有先填测试 AppID |
| **游戏方向** | 横竖屏，按画面选 | ⚠️ **本项目目标是竖屏**，选**竖屏** |
| **导出路径 / Build Path** | 生成小游戏工程的位置 | 例如 `D:\NewOne\Client-Dice\Builds\WechatMiniGame`（**不要**再用 `Builds\WxMiniGame`，那是 WebGL 产物，留着做对照组） |
| 小游戏项目名称（按需） | 导出的小游戏项目名 | 可填 `RuneDice` |
| **游戏资源CDN** | 游戏资源 CDN 根目录 | 见下方说明 |

> 💡 **「游戏资源CDN」为什么对我们是好消息**：手册 §8 说「如未使用 AutoStreaming，请将**首包数据文件**上传到微信小游戏页面填写的 `游戏资源CDN` 根目录」。
> 也就是说 **数据文件可以外置到 CDN，不占主包**。这直接缓解了我们最担心的「4 MiB 只剩 111 KB」 —— 上次那 911 KB 的 `data.br` 里很大一部分有机会移出主包。
> ⚠️ 但**具体能移多少、主包最终多大，必须以真实小游戏产物实测为准**，现在不要下结论。

## 第 4 步 · 两项能显著减小首包的设置（手册 §4、§5）

### 4.1 纹理压缩改 ASTC
手册原文：**File → Build Settings → Player Settings** 或 **Edit → Project Settings → Player** → 把 **Texture Compression** 改为 **ASTC** 并保存。
手册提示：**首次切换到 ASTC 时，Texture 压缩格式将会被转换，需要较长的时间**；开启后小游戏在移动端运行可节省大量内存和显存。

### 4.2 Graphics API 只留 WebGL 1 或 2
手册原文：**Edit → Project Settings → Player → Other Settings** → **取消勾选 Auto Graphics API**，**仅保留 WebGL 1 或 WebGL 2**。
目标：**减少 shader 变体数量，从而减小首包和启动时间**。
- 用 **WebGL 1** 时，若 **Lightmap Encoding** 为 **High Quality**，改为 **Normal**。
- **iOS 用 WebGL 2.0** 需系统 >15.0 且开 iOS 高性能模式，否则可能进游戏白屏。

> ⚠️ **本项目注意**：这两项都在改工程设置（`ProjectSettings`）。**由你自己在 GUI 里点**，我不代劳。
> 建议**单独记一下改前的值**，万一要回滚。

## 第 6 步 · 成功判据（硬门槛，缺一即失败）

手册 `UploadWeixinMiniGame.html` 明确：微信开发者工具导入时要选 **`wechat/minigame`** 文件夹。
所以 **导出目录下必须能找到 `wechat/minigame`**，且其内**同时存在**：

| 文件 | 作用 |
|---|---|
| `game.js` | 小游戏入口脚本 |
| `game.json` | 小游戏配置（**没有它就无法导入**） |
| `project.config.json` | 微信项目配置（`appid` 等） |

**三者缺一 ⇒ 未转换成功，不得导入开发者工具。** 这一步是 A1 的验收线。

## 第 7 步 · （转换成功后）导入微信开发者工具验证

手册 `UploadWeixinMiniGame.html` §1~§3：
1. 装**微信开发者工具**：`https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html`
2. 打开微信开发者工具 → 选 **Mini Game（小游戏）** 工程类型 → 点 **import（导入）** → 选 **`wechat/minigame`** 文件夹。
3. 打开 **Simulator（模拟器）** 与 **Debugger（调试器）** 看画面与调试信息；点右侧 **Compile（编译）** 可重启小游戏。

手册提到的两个运行期提示：
- 若报「**插件未授权使用 添加插件**」→ 点「添加插件」，并确认是否用了**测试游戏 AppID**。
- CDN 未开 gz/br 压缩会在 log 里提示；微信小游戏已自动带 `gzip,deflate,br`，**无需额外操作**。

> 💡 **顺手验掉那条悬案**：微信侧上传时会检查主包体积。**这里报不报 `exceed max limit`，是判定「4M 是 4096KB 还是 4000KB」的唯一 100% 方法**（方案 §17.1 的待办）。

## 第 8 步 · 请回传给我的东西

1. **导出目录的完整文件树**（至少根目录 + `wechat/minigame/` 一层）：
   ```cmd
   dir /s /b "<你的 Build Path>"
   ```
2. **是否出现 `game.js` / `game.json` / `project.config.json`**（A1 的验收线）。
3. **体积**：主包（代码包）与总量各多少字节：
   ```cmd
   powershell -NoProfile -Command "Get-ChildItem '<你的 Build Path>' -Recurse -File | Measure-Object -Property Length -Sum | Select-Object Count,Sum"
   ```
4. **Build 时 Editor.log 或 Console 的关键输出**（打包后 Console 里关于平台/转换的行）。
5. 第 1 步若装 SDK，**装的是 Git 还是插件包**、`Assets\` 下是否出现了 `WebGLTemplates` + `WX-WASM-SDK`。

拿到第 1~3 项，我就能给出**真实的**「主包 ≤4MB / 总量 ≤30MB」判定，并把 A1 从 FAIL 结案。
