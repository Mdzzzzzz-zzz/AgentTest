## 0. 一句话结论

**【已验证】** 本次崩溃是**两个独立故障叠加**：

1. **模块裁剪把 `com.unity.modules.assetbundle` 裁掉了** → SDK 的 `Wx` 程序集编译失败（`Runtime/WXBase.cs:884` CS0103）→ 连带把 `WxEditor` 也拖挂 → **SDK 的微信子平台根本没注册**；
2. 于是构建**只能**落到**引擎内置的 `WeChat` 子平台**，其 `DefaultWeChatMiniGameSettings.ApplySettings` 去加载**只在"插件模式"存在的** `Assets/WX-WASM-SDK-V2/Editor/MiniGameConfig.asset` → 加载失败 → `JsonUtility.FromJsonOverwrite(json, null)` → `ArgumentNullException`。

**修复 = ①装回 `assetbundle` 模块；②选对子平台（SDK 的 `WeChat:微信小游戏`，**不是**引擎内置 `微信小游戏`）；③给 Build Profile 填上非空 Build Path。** 三步都在 GUI 里点，不用改代码。

## 2. 根因（分条 + 证据）

### 根因 1 · `com.unity.modules.assetbundle` 被裁掉 ⇒ SDK 编译失败（对应 S1）

- **【已验证】** `Packages/manifest.json` 的 `dependencies` 里**没有** `com.unity.modules.assetbundle`（现有模块仅 animation / audio / imageconversion / imgui / jsonserialize / physics / physics2d / screencapture / ui，外加 SDK 与 ide/test）：
  ```json
  "com.qq.weixin.minigame": "https://github.com/wechat-miniprogram/minigame-tuanjie-transform-sdk.git",
  "com.unity.modules.animation": "1.0.0",
  ...（无 com.unity.modules.assetbundle）
  ```
- **【已验证】** `Library/PackageCache/com.qq.weixin.minigame@a09d4b29da/Runtime/WXBase.cs:884`：
  ```csharp
  var ab = AssetBundle.LoadFromMemory(abBytes);   // ← GetWXFont 内
  ```
  `AssetBundle` 类型属于 **`UnityEngine.AssetBundleModule`**；模块被裁 ⇒ 类型不存在 ⇒ CS0103。
- **【已验证】** SDK 自身**没有**声明该依赖：`Library/PackageCache/com.qq.weixin.minigame@a09d4b29da/package.json` 全文
  `{"name":"com.qq.weixin.minigame",...,"version":"0.1.1",...,"dependencies":{}}`
  ⇒ 引擎**不会**因为装了 SDK 就自动把 `assetbundle` 模块补回来。
- **【已验证】** 两段 asmdef 决定了"连坐"：
  - `Runtime/WxWasmSDKRuntime.asmdef`：`name:"Wx"`、`includePlatforms: []`（含编辑器）、`noEngineReferences: false`
  - `Editor/WxWasmSDKEditor.asmdef`：`name:"WxEditor"`、`includePlatforms:["Editor"]`、`references: ["Wx","Unity.InstantGame.Editor"]`
  ⇒ **`Wx` 编译失败，引用它的 `WxEditor` 必然一起失败。**
- **【已验证】**（**连坐第 2 条证据 · 实锤**）`Library/ScriptAssemblies/` 实测 **38 个文件，没有 `Wx.dll`、也没有 `WxEditor.dll`**；而 `DiceDemo.Runtime.dll`、`DiceDemo.DemoA/DemoB/DemoC.dll`、`DiceDemo.M1.Tests.dll`、`DiceDemo.M1.Editor.dll`、`FindReference2.Editor.dll`、`UnityTcp.*.dll`、`UnityEditor.UI.dll` 等**全部都在**。⇒ `Wx` 编译失败后**根本没产出程序集**，引用 `["Wx", …]` 的 `WxEditor` 自然也编不出来。
- **【已验证】** ⇒ `Editor/BuildProfile/WeixinSubplatformInterface.cs:14-21` 的 `[InitializeOnLoad] WeixinSubTargetManager` 静态构造**从未执行** ⇒ `MiniGameSubplatformManager.RegisterSubplatform(new WeixinSubplatformInterface())` **从未被调用** ⇒ 微信 SDK 子平台**未注册**、下拉里看不到（→ 见 §3 的**顺序陷阱**）。
- **✅ 可复现判据（装模块是否生效的直接证据）**：执行 §3 第 1 步装回 `assetbundle` 并等重编译后，`Library/ScriptAssemblies/` 下应**新出现 `Wx.dll` + `WxEditor.dll`**；同时 Console 的 `CS0103` 消失。三者同时满足即第 1 步成功。

## 3. 修复步骤（GUI-only，逐步照做）

> 全程在**编辑器里点**，不要跑 `-batchmode`（沙箱会挂，见手册 §5）。

> ### ⚠️ 顺序陷阱（**先看这条，否则你会以为菜单写错了**）
> **装模块之前，Subtarget 下拉里根本不会有 `WeChat:微信小游戏` 这一项 —— 只有一个引擎内置的「微信小游戏」。**
> 因为 `WxEditor` 从未编译成功（见根因 1 的 `ScriptAssemblies` 证据），`WeixinSubTargetManager` 的 `[InitializeOnLoad]` 从未执行，`RegisterSubplatform` 从未被调用。
> **所以正确顺序是：① 先装 `com.unity.modules.assetbundle` → ② 等重编译、确认 `Wx.dll`/`WxEditor.dll` 已产出且 CS0103 消失 → ③ 这时下拉里才会新出现 `WeChat:微信小游戏`，再选它 → ④ 填非空 BuildPath → Build。**
> **选项 `WeChat:微信小游戏` 的出现，本身就是「第 1 步修复生效」的第一个信号。** 在第 1 步完成前去找它 = 找不到，这是预期行为，不是文档写错。

### 第 1 步 · 装回 `assetbundle` 模块（治 CS0103，**最关键**）

1. 菜单 **`Window → Package Manager`**。
2. 点左上角 **`+`** → 选 **`Add package by name…`**。
3. 在 **Name** 填 `com.unity.modules.assetbundle`（**Version 留空**）→ 点 **`Add`**。
4. 等待编译完成。**期望（三条同时满足才算成功）**：① Console 里**不再出现** `WXBase.cs(884,34): error CS0103 ... 'AssetBundle'`；② `Packages/manifest.json` 的依赖里重新出现 `"com.unity.modules.assetbundle": "1.0.0"`；③ **`Library/ScriptAssemblies/` 下新出现 `Wx.dll` 与 `WxEditor.dll`**（装模块前实测这两个文件**不存在**，见根因 1 的连坐证据）。
5. **【待验证】**：`Project → Assets` 下（Package Manager 左列切到 **`In Project`**）应能看到 **Asset Bundle** 模块已勾选。

> **备选方案（二选一，由你定）**：直接编辑 `Packages/manifest.json`，在 `dependencies` 里加一行 `"com.unity.modules.assetbundle": "1.0.0",`。**推荐还是走 Package Manager**——省去手改与版本对齐风险。

> ⚠️ 若是**有意**为压体积裁掉 assetbundle 的：**SDK 依赖它**（`WXBase.cs:884`），小游戏目标下**不能裁**。裁包请改走其他杠杆（手册 §6 / §10.4）。

### 第 2 步 · 确认 SDK 子平台已注册

1. 编译干净后，菜单 **`File → Build Settings`**。
2. 左侧平台列表选 **`MiniGame`**（若未切换先点 **`Switch Platform`**）。
3. 看右侧 **`Sub Platforms`** 区域。
4. **期望**：出现 **两个**可区分的微信项 ——
   - 引擎内置：显示名 **`微信小游戏`**（hostName `WeChat`）；
   - **SDK 提供**：`WeixinSubplatformInterface.GetSubplatformName()`（`WeixinSubplatformInterface.cs:37-40`）返回的**字面量** **`WeChat:微信小游戏`**。
5. **【待验证】**：你实际看到的下拉条目文字/数量（这是 Q2 里我无法在沙箱坐实的唯一一点，见 §5）。

> 反查证据（【已验证】）：`Editor/BuildProfile/WeixinSubplatformInterface.cs:37-40` `GetSubplatformName() => "WeChat:微信小游戏"`；引擎侧 `UnityEditor.CoreModule.dll` 含 `MiniGameSubplatformManager` / `RegisterSubplatform` / `GetAllSupportedSubplatforms` / `GetActiveSubplatformEnum` 等符号，内置子平台显示名含 `微信小游戏`（ASCII 亦见 `WeChat` / `WeChatBuildProfile` / `DefaultWeChatBuildProfileHelper`）。

### 第 3 步 · 选**对**子平台（**核心动作**）

- **必须选** 带 SDK 前缀的那一项：**`WeChat:微信小游戏`**。
- **绝不能选** 引擎内置的那一项：**`微信小游戏`**（它走 `DefaultWeChatBuildProfileHelper` → 就是本次崩溃路径）。

**【已验证】为什么这样就能绕开崩溃（Q3 结论）**：SDK 的 `WeixinSubplatformInterface.Build(buildProfile, options)`（`WeixinSubplatformInterface.cs:53-96`）**全程不调用** `DefaultWeChatMiniGameSettings.ApplySettings`；它自己做：
- `WechatBuildPreprocess`（`:200-239`）→ 设模板路径 `Packages/com.qq.weixin.minigame/WebGLTemplates/WXTemplate2022TJ`、压缩 `Disabled`、linker `Wasm` 等；
- `CallDoExport`（`:241-263`）→ `UnityUtil.GetEditorConf()` 取**SDK 自己的** `MiniGameConfig.asset` → `ApplyMiniGameSettingsToConfig` → `WXConvertCore.DoExport()`。

即便 profile 里仍是内置 `DefaultWeChatMiniGameSettings`，SDK 也在 `:124-132` **专门兼容**该类型（用 `JsonUtility` 逐字段搬到自己 config，目标是**已初始化的** `config.ProjectConf`，**不会**出现 `null` 目标）。⇒ **只要走 SDK 子平台，S2/S3 两项都不会发生。**

### 第 4 步 · 处理 Build Profile

- 磁盘上现有 `Assets/Settings/Build Profiles/MiniGameProfile.asset` 绑定的是**内置类型**（`:1414`），且其 `:1437` `bgImageSrc` 指向不存在的 `Assets/WX-WASM-SDK-V2/...`。
- **推荐做法（最省事、最干净）**：
  1. 在 **`File → Build Settings → Sub Platforms`** 选中 **`WeChat:微信小游戏`**；
  2. 点 **`Add Build Profile`** 新建一个 profile（此时应绑到 SDK 的 `WeixinMiniGameSettings`）；
  3. 选中它，在 Inspector 里填 **Build Path**（**非空**绝对路径，例如 `D:\NewOne\Client-Dice\Build\WeixinMiniGame`）；
  4. 配置 **project conf**（`appid` 等）：入口 **`微信小游戏转换平台 → 更多配置项`**（或 `扩展菜单 → debug`）。
- **【待验证】**：新建 profile 后，其 `miniGameSettings` 是否已是 `WeixinMiniGameSettings`（判据：Inspector 的 **MiniGame Platform Settings** 分组是否正常展开、能填 appid；或存盘后看 asset 里 `type:` 是否不再含 `DefaultWeChatMiniGameSettings`）。
- 旧的 `MiniGameProfile.asset` 可**保留不动**（它不会被构建除非你勾选它）；**不要**勾选那个 `New WeChat Profile`（空 BuildPath 的那个）。

### 第 5 步 · 构建 + 判据

1. `File → Build Settings` → 勾选**第 4 步新建的那个** profile 左侧小框（确认其 Build Path 非空）→ 点右下 **`Build`**。
2. **期望成功判据（硬门槛）**：输出目录**同时**出现 **`game.js`**、**`game.json`**、**`project.config.json`**（另有 `wasmcode/`、`data-package/` 分包目录）。
   - 反查证据（【已验证】）：SDK 转换器 `Editor/WXConvertCore.cs:83` `defaultTemplateDir => isPlayableBuild ? "playable-default" : "wechat-default"`；`:1543` 与 `:2286` 明确以 `{"game.js","game.json","project.config.json","check-version.js"}` 为落盘清单；模板源就在包内 `Runtime/wechat-default/{game.js(8,334B), game.json(1,068B), project.config.json(1,722B)}`。
3. 若仍失败 → 进 §4。

> **可选**：第 5 步若走 GUI 很慢，也可改用 build profile 的代码入口（`BuildPipeline.BuildMiniGame(buildProfile)`，见手册 §10.3），但**前提仍是第 1~4 步已成立**。

## 6. 附 · SDK 的两种引入模式（解释 S2/S3 的"路径"从哪来）

**【已验证】** `Editor/wx-editor.xml:322-334`：
- `UnityUtil.GetWXSDKRootPath()`：「获取当前插件模式下 WX-WASM-SDK-V2 的真实绝对路径；如果是 **Unity 版本**，返回 `.../Assets/WX-WASM-SDK-V2`；如果是 **Tuanjie 版本**，若是**导入插件模式**，也返回 `.../Assets/WX-WASM-SDK-V2`；若是 **Package 模式**，则返回插件的真实路径，如 `.../temp/xxxxx/com.qq.wx.minigame`。」
- `UnityUtil.GetSDKMode()`：「返回 `SDKMode.Assets` 资源目录模式；`SDKMode.Package` 包模式。」

**【已验证】** 本工程是 **Package 模式**：SDK 在 `Packages/manifest.json` 以 git URL 引入、实体在 `Library/PackageCache/com.qq.weixin.minigame@a09d4b29da/`，`Assets/` 下**没有** `WX-WASM-SDK-V2/`。

⇒ **根因 2 的"路径错配"本质**：引擎内置的 `DefaultWeChatMiniGameSettings` 只认 **Assets 插件模式的硬编码路径**（CoreModule.dll 里那串 `Assets/WX-WASM-SDK-V2/...`），**不认** Package 模式；而 SDK 自己的转换器（`WXConvertCore.cs:394/466/591/625/2393`）用 `if (GetSDKMode()==Package)` **正确处理两种模式**。所以：**跟着 SDK 走就没事，让引擎内置 helper 来跑就会撞墙。**

> 附带提示（【已验证】）：SDK 自身也有一个同样的默认值 `Editor/WXConvertCore.cs:93 defaultImgSrc = "Assets/WX-WASM-SDK-V2/Runtime/wechat-default/images/background.jpg"`，但它在 Package 模式分支里会被替换/忽略；**不要**因为这个字符串就以为必须建 `Assets/WX-WASM-SDK-V2/`。

## 7. 附 · 判定：profile 里 `weixinMiniGameTemplate=…WXTemplate2022TJ` 是哪来的（"单一根因"是否需加例外）

**问题**：`MiniGameProfile.asset` 的 PlayerSettings 段存了
`weixinMiniGameTemplate: PATH:D:\NewOne\Client-Dice\Library\PackageCache\com.qq.weixin.minigame@a09d4b29da\WebGLTemplates\WXTemplate2022TJ`。

**结论：是 (b) —— 更早某次 `Wx`/`WxEditor` 编译成功状态下写下的残留值；(a) 被证伪。证据强度：强（接近确凿）。**

**对结论强度的影响**：本报告的**主根因链不变**（当前 `Wx`/`WxEditor` 确实编译失败 → DK 子平台确实未注册 → 崩溃栈确实出自引擎内置 helper）。此残留值只是"该 profile 曾经走过 SDK 路径"的历史痕迹，**不构成反例**，但值得加一句**例外说明**：**profile 里出现 `WXTemplate2022TJ` 不代表 SDK 当前可用**（它的来源可能是旧状态），一切以 `ScriptAssemblies/` 里是否有 `Wx.dll`/`WxEditor.dll` 为准。

**未能坐实的一点**（诚实标注）：我**无法确定该值写入的精确时刻**（是某次 SDK 构建的 `WechatBuildPreprocess`，还是 SDK 设置面板在可编译状态下写入）——两者都属 `WxEditor`，结论不变；但"何时"只能由你的操作历史解释。
