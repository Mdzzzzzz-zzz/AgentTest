```cmd
cd /d D:\NewOne\Client-Dice
"C:\Program Files\Tuanjie\Hub\Editor\2022.3.62t14\Editor\Tuanjie.exe" ^
```

> `^` 是 cmd 续行符，也可以整条写成一行、去掉所有 `^`。

判定：

- **成功** → 日志末尾 `M1三维构建完成：<路径>，大小=<字节数>`
- **失败** → 抛 `阶段一三维战斗构建失败：<结果>，错误数=<n>`，去日志搜 `error CS`

**副作用提示**：该方法内部会调 `SwitchActiveBuildTarget(StandaloneWindows64)`，可能触发一次资产重导入，首次耗时数分钟，属预期。

## 4. 字体链问题：已定论（原「第 2 步」）

### 4.1 结论

**5 套 NotoSans CJK 字体及全部 `.ttf` 都没有进包。** 进包的字体载荷只有 **Jersey10 拉丁字体的 Material + Atlas**，约 1MB 量级。

### 4.2 证据一：包内字符串检索

资产名以 ASCII 字符串存在序列化文件里，直接检索 `Builds\M1\Windows\RuneDiceM1_Data`：

| 检索词 | 命中文件数 | 说明 |
|---|---|---|
| `NotoSans` / `NotoSansSC` / `NotoSansJP` / `NotoSansKR` / `NotoSansTC` | **0** | CJK 字体族完全不在包内 |
| `.ttf` | **0** | 包内无任何 TTF |
| `Jersey10` | 1 | 仅 `sharedassets0.assets`，出现两次 |
| `Desktop_Wooden`（对照） | 1 | 桌面材质在包内 ✓ |
| `BattleFlow`（对照） | 3 | 代码在包内 ✓ |
| `符文`（对照） | 2 | 场景文本在包内 ✓ |

`Jersey10` 的全部命中上下文只有两条：

```
Jersey10-Regular SDF Material
Jersey10-Regular SDF Atlas
```

即只有该字体的**材质与图集纹理**，且图集体量仅约 0.99MB（`sharedassets0.assets.resS` = 991,680 字节）。

### 4.3 证据二：字节账目完全闭合

| 分项 | 字节 | MB |
|---|---|---|
| `TuanjiePlayer.dll` | 47,477,592 | 47.48 |
| `_Data/Managed`（托管运行时） | 24,454,352 | 24.45 |
| `_Data`（含 Managed / Resources） | 35,070,525 | 35.07 |
| `MonoBleedingEdge` | 9,333,942 | 9.33 |
| `RuneDiceM1.exe` | 464,384 | 0.46 |
| `TuanjieCrashHandler64.exe` | ~1,170,776 | 1.17 |
| **合计** | **≈93,517,219** | **≈93.52** |

对照构建日志记载的 `大小=93514659`（93.51MB）——**误差仅 2,560 字节**。

且 `find _Data -type f -size +5M` **结果为空**：整个 `_Data` 里**不存在任何 >5MB 的文件**。

⇒ **包体账目已完全闭合，没有任何余量可以塞进一份 10.55MB 的 NotoSansSC。**

### 4.4 对 B1 的影响（重要）

- 「砍约 40MB 字体链」这一前提**不成立**。真正可砍的字体载荷约 **1MB**。
- **CJK 字体子集化仍然要做，但理由变了**：不再是"从包里砍掉 40MB"，而是"后续 UI 要显示中文，得自己装一份中文子集 TTF"（约 80–150KB）。工作量与收益都要重新评估。
- B1「一石三鸟」里仍然成立的两半：
  - **授权风险**（`Assets/DemoA/` 原作素材）
  - **散装 URP shader 隐患**（桌面 4 个材质指向 AssetRipper 导出的 `Universal Render Pipeline_Simple Lit.shader` 副本）
- 这三件事从"一个刀口切三样"变成"三件独立的小事"。
